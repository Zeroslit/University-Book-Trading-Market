# 04 数据库 ER 设计

## 1. 设计通则
- 主键统一 `id BIGINT UNSIGNED AUTO_INCREMENT`，时间统一 `created_at / updated_at DATETIME(3)`。
- **业务表必带 `school_id`**（`schools` 自身除外），并建 `idx_school_*` 索引；跨校共享表（`configs`、`banned_words`、`kb_articles`）用 `school_id NULL` 表示平台级。
- 金额统一用 `*_cents INT UNSIGNED`（分）存储，禁止浮点。
- 敏感字段：`*_enc`（AES-256-GCM 密文）、`*_last4`（脱敏展示）、`*_hash`（HMAC 盲索引，用于唯一约束与检索）。
- 状态列统一 `VARCHAR(32)` + 应用层枚举校验（状态机可从配置扩展，避免 ENUM 改表）。

## 2. 实体关系（文字版 ER）

```
schools 1 ── N users 1 ── N books 1 ── N book_images
                  │             └── N orders （buyer_id / seller_id 双向指向 users）
                  ├── N user_verifications（学生认证，可多次提交）
                  ├── N payment_accounts（收款绑定，脱敏）
                  ├── 1 wallet_accounts 1 ── N wallet_transactions
                  ├── N credit_logs（信誉分流水）
                  ├── N penalties（处罚）── N appeals（申诉）
                  ├── N reports（reporter_id / target）
                  ├── N threads 1 ── N replies ──（自关联 parent_id）
                  ├── N conversations（buyer_id / seller_id）1 ── N messages
                  ├── N notifications
                  ├── N tickets 1 ── N ticket_logs
                  ├── N chat_sessions 1 ── N chat_messages
                  └── N word_hits
orders 1 ── N order_status_log（状态流转快照，含操作人）
orders 1 ── N wallet_transactions（托管、放款、退款的资金去向可反查）
tickets N ── 1 orders / users（来源与关联对象）
configs：平台级（school_id NULL）与学校级配置，键值 JSON，带 version
```

## 4. 索引与性能要点
- 高频列表查询一律走 `(school_id, status, created_at)` 复合索引，避免跨校扫描。
- 图书/帖子/知识库使用 MySQL 8 全文索引（ngram 分词器）支持中文关键词检索。
- `orders.auto_confirm_at`、`tickets.first_response_due_at`、`tickets.resolve_due_at`、`credit_logs.expires_at` 建索引，供定时任务扫描。
- 所有唯一约束都由数据库保证，应用层校验只做友好提示（防并发穿透）。
