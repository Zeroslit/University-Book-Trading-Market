# 01 需求拆解与范围界定

## 1. 业务定位
面向全国高校的**教材循环交易平台**。平台按学校（`school_id`）分区运营：学生登录后直接进入本校图书库与论坛；
平台侧提供风控（违禁词、信誉分、处罚申诉）与客服（AI + 人工工单 + 资金仲裁）能力。

## 2. 角色拆解（RBAC）

| 角色 | role 枚举 | 数据可见范围 | 核心能力 |
| --- | --- | --- | --- |
| 学生（买家/卖家） | `student` | 本校（开启跨校专区时可见跨校池） | 注册认证、发布、搜索、发帖、评论、私信、下单、收货、提现、申诉 |
| 学校管理员/校园大使 | `school_admin` | 本校 | 本校内容审核、本校违规处理、本校数据看板 |
| 人工客服 | `support` | 按工单授权跨校 | 工单处理、订单快照、违规历史、裁定投诉、执行处罚、仲裁放款退款 |
| 平台管理员 | `platform_admin` | 全局 | 学校开通配置、词库阈值、跨校规则、全局封禁、全平台看板 |

> `support` / `platform_admin` 允许 `school_id = NULL`（工作域跨校），这是**唯一**允许为空的情形；
> 其接口不参与“本校过滤”，改走显式授权 + 审计留痕（见 `docs/06-多校隔离实现说明.md`）。

## 3. 功能范围

### 3.1 一期交付（In）
1. **多校架构**：学校主数据、按省/市搜索、申请开通学校、学校级独立配置（服务费比例、可发布品类、是否需认证、跨校专区开关）。
2. **账号体系**：手机号 + 短信验证码注册、密码登录与微信模拟登录、`school_id + student_no` 联合唯一、学生认证（学生证/校园邮箱 + 人工审核）。
3. **收款绑定**：微信/支付宝/银行卡，仅存后四位与哈希；换绑/解绑需短信二次验证 + 24 小时冷却。
4. **图书库**：多图上传（前端压缩长边 ≤1080px）、图书 CRUD、关键词/课程/价格/成色筛选排序、详情页（卖家信誉分、成交量、联系卖家、立即购买）。
5. **论坛**：求书帖/转让帖、图片、搜索、评论与回复，发帖评论违禁词检测。
6. **私信**：基于图书或帖子发起会话、会话列表、聊天窗口、图片消息、违禁词过滤。
7. **交易与资金托管**：完整状态机、超卖防护、7 天自动确认、争议冻结、流水留痕、幂等。
8. **钱包**：余额/冻结、模拟充值、提现（需绑定收款方式 + 已实名）、明细按订单号追溯。
9. **通知**：站内信（必达）+ 微信订阅消息（模拟适配器）。
10. **信誉分与违规**：100 分起始、加减分规则、五档权限联动、明细流水。
11. **投诉-处罚-申诉**：举报 → 受理 → 48h 举证 → 裁定 → 处罚扣分 → 3 天申诉期 → 复审回滚。
12. **违禁词四级体系**：L1 提示打码 / L2 拦截 / L3 拦截+扣分+记违规 / L4 删除+转人工+封禁；归一化检测；命中留痕与白名单。
13. **客服体系**：AI 客服（FAQ + 订单查询 + 动作触发）、转人工条件、人工工单队列（抢单/快捷回复/一屏风控/一键处罚/仲裁）、SLA 超时升级。
14. **管理后台**：学校开通配置、内容审核、词库阈值、用户管理、订单仲裁、工单统计、投诉处罚看板。

### 3.2 一期不做（Out，明确边界）
- **不接入真实支付**：支付/退款/提现均为平台内**模拟实现**（`mock-pay`），只产生流水与状态，不对接微信/支付宝商户。
- **不做真实银行卡鉴权**：不做四要素验证与代付通道，卡号只保存后四位与哈希。
- **不做真实小程序**：前端为响应式 Web（Vue3）；小程序化与合规建议见 `docs/09-支付与小程序上线合规建议.md`。
- **不做真实 OCR**：图片 OCR 走可插拔适配器，一期默认 `disabled` + 人工抽检，接口与留痕已就绪。
- **不做真实短信**：短信走 `sms.service.js` 适配器，开发环境为 `console` 驱动，验证码存 Redis（60s 频控 / 5 分钟有效 / 错误次数上限）。
- **不做真实实名认证**：以学生证/校园邮箱人工审核替代，实名信息只存脱敏项。

## 4. 硬性业务约束 → 实现落点

| 约束 | 落点 |
| --- | --- |
| 业务数据必须带 `school_id`，服务端强制注入过滤 | `middleware/school-scope.js`，全部 SQL 强制 `school_id = ?`；集成测试覆盖跨校越权拦截 |
| 规则阈值配置化，禁止写死 | `configs` 表 + `services/config.service.js`（平台默认 → 学校覆盖 → 缓存）；种子数据写入默认阈值 |
| 资金/处罚/工单/词命中全留痕 | `wallet_transactions`、`penalties`、`ticket_logs`、`word_hits`、`audit_logs`、`order_status_log` |
| 资金操作事务 + 幂等 | `db/tx.js` 事务封装 + `wallet_transactions.idempotency_key` 唯一约束 + `idempotency_records` |
| 敏感信息脱敏、分级授权、保存期限 | `lib/crypto.js`（AES-256-GCM）、`lib/mask.js`、`audit_logs`、`jobs/retention.job.js` |
| 关键流程单测 | `server/tests/unit` + `server/tests/integration` |

## 5. 交易状态机

```
pending_payment ──pay──▶ paid(资金托管中) ──ship──▶ shipped(待确认收货, 7 天自动确认倒计时)
   │ cancel(未付款)        │ refund_request ─▶ refund_requested ─agree─▶ refunded
   ▼                       │                                  └reject─▶ paid
cancelled                  │ dispute ─▶ disputed(冻结放款 + 暂停自动确认)
                           │              └─仲裁─▶ arbitrated_refund / arbitrated_release
shipped ──confirm──▶ completed(放款给卖家并扣平台服务费)
shipped ──return_request──▶ return_requested ─agree─▶ refunded(退货退款, 托管款全额退回买家)
```
迁移表由 `configs.order_state_machine` 配置，代码只做校验与执行，不硬编码分支。

## 6. 信用分档位（默认值，全部来自配置，可在后台改）

| 档位 | 分值 | 权限影响 |
| --- | --- | --- |
| 优秀 | 90–100 | 优先展示、提现即时到账 |
| 良好 | 70–89 | 正常 |
| 受限 | 50–69 | 最多挂 3 本书、提现延迟 24 小时 |
| 高风险 | 30–49 | 禁止发布新书 |
| 高危 | 0–29 | 禁止交易，仅可浏览 |

## 7. 验收口径
每阶段均交付：可运行接口 + 种子数据 + 单元/集成测试 + 手工验证步骤（见 `docs/08-分阶段交付与验证.md`）。
