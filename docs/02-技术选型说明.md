# 02 技术选型说明

## 1. 选型总览

| 层 | 选型 | 版本 | 理由 |
| --- | --- | --- | --- |
| 前端 | Vue 3 + Vite + Vue Router + Pinia | Vue 3.4 / Vite 5 | 组合式 API，构建快；单页应用同时适配 PC 与手机浏览器 |
| 后端 | Node.js + Express | Node 20 / Express 4 | 生态成熟、分层清晰，便于按模块拆分 |
| 数据库 | MySQL 8 | 8.0 | 事务 + 行锁（`SELECT ... FOR UPDATE`）满足托管资金与防超卖；生成列唯一索引做兜底约束 |
| 缓存/限流 | Redis 7 | 7.x | 验证码、接口限流、配置缓存、会话与幂等锁 |
| 图片 | 本地目录或对象存储，库里只存 URL | - | 前端压缩长边 ≤1080px 后上传，便于迁移 OSS/COS |
| 鉴权 | JWT（access + refresh） | - | 无状态易扩展；`jti` 支持登出黑名单（Redis） |
| 参数校验 | Zod | 3.x | Schema 声明式校验，错误统一映射为业务错误码 |
| 测试 | node:test（Node 内置）+ supertest | Node 20 | 零额外测试框架依赖，CI 成本低 |
| 部署 | Docker Compose | - | 一键拉起 MySQL + Redis + API + Web |

## 2. 关键取舍

### 2.1 用生成列唯一索引承载“一本书同时只能有一个有效订单”
MySQL 没有带 `WHERE` 的部分唯一索引，而这条规则是**资金安全**红线。方案：在 `orders` 上定义 STORED 生成列
`active_book_id`，仅当订单处于进行中状态时等于 `book_id`，否则为 `NULL`；再对 `active_book_id` 建唯一索引。
MySQL 唯一索引允许多个 `NULL`，等价于“部分唯一索引”。配合下单事务里的 `SELECT ... FROM books WHERE id = ? AND school_id = ? FOR UPDATE`，
形成**行锁 + 唯一索引**双重防护（并发下单只会有一个成功，另一个收到业务错误码）。

### 2.2 余额由流水推导，账户余额字段只是缓存
需求明确“禁止直接修改余额字段”。实现：`wallet_transactions` 为唯一事实来源（append-only）；
`wallet_accounts.balance_cents / frozen_cents` 仅在**同一事务内**随流水更新，作为读性能缓存；
`wallet.service.assertConsistency()` 校验“流水求和 == 账户余额”，集成测试与巡检任务都会调用。

### 2.3 规则阈值全部落库
信誉分档位、处罚梯度、违禁词动作、SLA 时限、服务费比例、品类白名单、状态机迁移表均存 `configs` 表，
读取顺序为「学校级覆盖 → 平台级默认 → 抛错」，**不提供硬编码兜底**，改规则无需发版。

### 2.4 多校隔离的三级防护
1. **中间件**：`schoolScope` 解析并锁定 `req.schoolId`（学生取自 JWT，管理角色取自显式参数 + 权限校验）；
2. **数据访问层**：repository 函数签名强制要求 `schoolId`，SQL 一律 `AND school_id = ?`，并提供 `assertSameSchool()`；
3. **数据库**：核心表 `school_id` 建索引，并作为联合唯一键组成（如 `users(school_id, student_no)`）。

### 2.5 AI 客服的权限边界
AI 只挂载**只读工具**（订单查询、物流查询、信誉分查询、知识库检索）与**申请类工具**（发起退款申请、创建工单）。
放款、退款、处罚等资金与处置动作在 `ai-cs.service.js` 的工具注册表里**根本不注册**，从代码层面保证“AI 无权直接放款或退款”。

## 3. 依赖方向

```
routes → service → repository(SQL) → db
        ↘ lib（errors / crypto / normalize / state-machine）
所有模块 ⇢ services/config.service（阈值）· services/notify.service（通知）· services/audit.service（留痕）
```
单向依赖：禁止 repository 反向调用 service；禁止在 routes 里直接写 SQL。

## 4. 安全与合规基线
- 密码 `bcryptjs`（cost 10）；手机号/姓名/收款账号 AES-256-GCM 加密 + HMAC-SHA256 盲索引（唯一性与检索）。
- JWT access 2h / refresh 7d；`jti` 黑名单存 Redis，支持“禁止登录”封禁即时踢下线。
- 全站限流：默认 300 req/min/IP；登录、验证码、下单、提现等敏感接口单独更严阈值，阈值存 `configs.rate_limit`。
- 所有写操作写 `audit_logs`（谁、何时、对什么、做了什么、IP）。
