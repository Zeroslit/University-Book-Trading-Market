# 08 分阶段交付与验证

每个阶段都可独立运行与验证。通用前置：

```bash
docker compose up -d mysql redis        # 或使用已有 MySQL 8 / Redis 7
cd server && npm install
npm run migrate && npm run seed         # 建表 + 种子数据
npm run dev                             # http://localhost:3000/api/v1
```

| 阶段 | 交付内容 | 验证方法 |
| --- | --- | --- |
| 0 设计 | `docs/01`~`09` 设计文档、目录结构、ER、接口清单 | 阅读文档；对照代码目录结构一致 |
| 1 多校与账号 | `schools`/`users`/`user_verifications`/`payment_accounts`/`school_applications`；注册登录、短信验证码、认证审核、收款绑定与 24h 冷却；`schoolScope` 中间件 | `npm run test:unit`（脱敏、配置读取）；`npm run test:integration` → `isolation.test.js`（跨校越权拦截）、`auth.test.js`（学号冲突、认证前禁发帖）；手工：`POST /auth/register` 后 `GET /auth/me` 直接带出 `schoolId` |
| 2 图书库 | `books`/`book_images`、图片上传、筛选排序、详情 | `book.test.js`：发布（未认证被拒）、筛选、下架后不可下单；手工：上传图片得到 URL 并发布成功 |
| 3 论坛 | `threads`/`replies`、搜索、评论回复、发帖评论违禁词 | 手工发含 L2 词的帖子 → 返回 `BANNED_WORD_BLOCKED` 且 `word_hits` 有记录 |
| 4 私信 | `conversations`/`messages`、会话复用、已读、违禁词 | 手工：图书详情「联系卖家」→ 会话创建 → 双向发消息；重复点击不产生新会话 |
| 5 交易托管 | `orders`/`order_status_log`/`wallet_accounts`/`wallet_transactions`/`withdraw_requests`；状态机、托管、放款扣费、退款、争议冻结、7 天自动确认 | `order-concurrency.test.js`（20 并发下单只成功 1 单）、`escrow.test.js`（支付→发货→确认收货后卖家到账 = 售价 - 服务费、平台费入账、流水可追溯）、`refund.test.js`（退款后买家全额、托管归零） |
| 6 通知 | `notifications` + 通知服务，覆盖订单/投诉/处罚/封禁/认证/工单/词提醒 | 手工：走完一单 → 双方站内信存在；`GET /notifications` 可见 |
| 7 信誉分与违规 | `credit_logs`、档位权限联动、`reports`/`penalties`/`appeals` 链路 | `credit.test.js`（档位边界、扣分、回滚）、`penalty.test.js`（第 3 次禁言 3 天、第 5 次封禁 7 天、第 10 次永久、严重一票永久）、`report.test.js`（举报→受理→举证→裁定→申诉回滚） |
| 8 违禁词 | `banned_words`/`word_hits`、四级处置、归一化、白名单、累计禁言 | `word-normalize.test.js`：全角/繁简/拼音谐音/插符号/零宽字符均可命中，白名单不误伤 |
| 9 客服工单 | `tickets`/`ticket_logs`/`chat_sessions`/`chat_messages`/`kb_articles`、AI 三层能力、转人工、SLA | `ticket.test.js`（抢单乐观锁、SLA 计算、超时升级）、`ai-cs.test.js`（FAQ 命中、订单查询、AI 无权放款的工具白名单、连续 2 轮未解决自动转人工） |
| 10 管理后台 | 后台接口 + 前端后台页面（学校配置、内容审核、词库、用户、仲裁、看板） | 浏览器登录 `platform_admin` 账号 → 修改服务费比例 → 新订单按新比例计费 |

## 前端手工验收清单（端到端）
1. 用种子账号（密码 `Test@123456`）登录 → 直接进入本校图书库。
2. 发布一本教材（多图）→ 另一个学生搜索到 → 私信沟通 → 下单 → 模拟支付 → 卖家发货 → 买家确认收货。
3. 钱包页看到：买家支出、卖家「余额 + 售价 − 服务费」、平台服务费流水，全部可按订单号追溯。
4. 发一条含「代写」的帖子 → 被拦截并提示具体违规词与位置，信誉分 −3，`credit_logs` 与 `word_hits` 各有一条。
5. 举报一本书 → 客服受理 → 裁定成立 → 被投诉人收到处罚通知 → 3 天内申诉 → 复审通过后信誉分回滚。
6. AI 客服问「我的订单到哪了」→ 返回订单状态；问「我要退款」→ 创建退款申请 + 工单，而不是直接退款。

## 失败排查
| 现象 | 原因/处理 |
| --- | --- |
| 接口返回 `CONFIG_MISSING` | 配置未初始化，执行 `npm run seed` |
| 集成测试跳过 | 未设置 `TEST_DB_HOST`；集成测试需要 MySQL，见 `server/tests/helpers/db.js` |
| 登录后看不到图书 | 学校未开通或图书未上架；检查 `schools.status` 与 `books.status` |
| Redis 不可用 | 开发环境会降级为内存实现并打 warn 日志（仅开发模式） |
